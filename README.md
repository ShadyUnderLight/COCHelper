# COC 助手：Builder Roadmap

一个原生 SwiftUI macOS 本地原型，第一阶段聚焦“建筑工人长期规划器”。目标不是简单回答“还剩多少天”，而是在建筑、科技、英雄、资源和部落战体验之间给出可解释的取舍。

## 当前已实现

- 30 / 90 / 180 天规划窗口。
- 1–6 个建筑工人和大本营等级输入。
- 休闲发展、部落战优先、联赛期间三种策略。
- 联赛保留英雄、大本营准备度、资源错峰、每日上线频率等约束。
- 六条工人时间线，以及独立的实验室科技队列。
- 每个工人的当前任务与剩余时间，可直接作为规划起点。
- 金币、圣水、暗黑重油的库存、容量和日均收入；资源不足会推迟任务而不是忽略成本。
- 英雄等级、升级剩余时间和部落战保护窗口；英雄任务会避开不可用时间。
- 版本化本地游戏数据目录：包含 schema、游戏版本、目录版本、来源状态和结构校验。
- 支持粘贴游戏内复制的原始账号 JSON：解析主村 / 建筑工人基地数组、重复记录、嵌套模块、计时器、加速状态和未知字段诊断；有快照时间时会将计时器、helper 冷却和加速冷却换算到导入时剩余值；确认后将快照保存在本机。
- 随 app 打包基于游戏 APK `logic/*.csv` 与简体中文本地化表生成的分区名称目录；建筑、兵种、英雄、战宠、装备、障碍物、皮肤、场景和季节防御模块会显示中文名，同时保留原始 `#dataID` 便于审计；更换 APK 时可用 `Tools/generate_account_name_catalog.py` 重新生成目录。
- 多村庄档案：每个账号独立保存 JSON 快照、规划参数和待升级项；侧边栏可切换村庄，按账号 `tag` 重复导入时自动更新对应档案。
- 导入账号 JSON 后，规划页优先展示已读取的主村 / 建筑工人基地数据和进行中记录；资源库存、工人编号与队列归属等缺失字段收进可选补充区，不会从演示账号复制。
- 启发式规划评分：规划平衡分、部落战友好度、建筑/科技同步度、资源压力。
- 可编辑的待升级项；输入会保存在本机 `UserDefaults`。
- 旧版本地保存数据可用默认值迁移到新的状态合同；规划器核心有 XCTest 覆盖。

## 运行

```bash
swift test
swift run COCHelper
```

生成可双击打开的本地 app：

```bash
./scripts/build_app.sh
open .build/COCHelper.app
```

也可以直接在 Xcode 中打开 `Package.swift`，选择 `COCHelper` scheme 运行。

## 重要边界

当前版本仍是本地启发式排程，不联网、不调用账号 API，也不宣称包含官方实时升级数据。账号 JSON 通过游戏内复制后粘贴到“账号数据”页面；导入确认后会按 tag 自动归档到村庄档案，并在规划页展示主村 / 建筑工人基地的快照记录。解析器保留原始文本，展示的计时器/冷却值按 `timestamp` 扣除快照年龄；没有时间戳时保留原始值并提示诊断。JSON 没有明确提供资源库存、工人总数、工人编号/队列归属和未来升级目标，因此这些字段不会被猜测；需要精排时可在规划页展开“补充规划数据”，再添加真实待升级项。默认版本化目录仍是 `demo-0.1`，游戏版本显示为“未绑定官方版本”；联赛日历、魔法物品库存与精确机会成本仍未接入。

## 下一阶段建议

1. 随游戏版本更新名称目录，并为不同 APK 版本保留可审计的目录快照。
2. 在用户确认后把账号快照投影到英雄状态、工人剩余时间和实验室队列，不猜测缺失的工人编号。
3. 增加实验室当前科技、剩余时间和科技资源消耗的账号状态录入。
4. 引入资源收入、每日登录和部落战日历的事件模拟，输出多个可比较方案。
