# #280 E5-03-A：Electron pre-cutover 发布准备

## 目标

建立可复现、可追溯且不会误称正式发布的 Electron 候选制品流水线，供 #281 纯 Electron 切换使用。

## 本切片交付

- Forge `package` / `make` / GitHub publisher 配置；
- macOS arm64 的 zip 与 dmg 候选制品；
- SemVer、numeric build number、commit SHA、catalog schema/gameVersion/buildTag/locale 注入；
- app resource 内的 `release-manifest.json` 与 `sbom.cdx.json`；
- 输出目录内的 `release-manifest.json`、CycloneDX SBOM 和 `artifact-manifest.json`；
- clean checkout runner：冻结依赖安装、format/lint/typecheck/test、隔离检查和 make；
- macOS DMG maker 的 `macos-alias` 原生 binding 在 clean runner 上由 release runner 显式 `node-gyp rebuild`，不依赖上游包缺失的 install hook；
- 手动 GitHub Actions workflow，默认生成 pre-cutover 制品，不执行发布；
- formal candidate 模式要求同时提供 #278 E2E 与 #279 性能证据引用，缺少任一引用则 fail-closed。

## 命令

普通 pre-cutover 制品：

```bash
pnpm release:prepare \
  --version=0.1.0-rc.1 \
  --build-number=1 \
  --platform=darwin \
  --arch=arm64
```

需要消费最终 E2E/性能证据时：

```bash
pnpm release:prepare \
  --version=0.1.0-rc.1 \
  --build-number=1 \
  --formal-candidate \
  --e2e-evidence=<issue-278-evidence-url-or-path> \
  --perf-evidence=<issue-279-evidence-url-or-path>
```

输出在 `release-artifacts/<version>-<build-number>/`；该目录被 `.gitignore` 忽略，不进入源码 commit。

## 验收边界

- candidate 只能来自 clean checkout；dirty source、缺失/非法 SemVer、缺失/非法 build number、无 catalog manifest 均失败；
- app package version/buildVersion 和 release manifest 使用同一版本与 build number；
- release manifest 记录 exact commit、source dirty 状态、catalog 四字段和 Electron/package-manager 版本；
- SBOM 只记录生产依赖和 Electron runtime，不把 `unsavedDependencies` 或测试依赖冒充生产依赖；
- artifact manifest 记录制品相对路径、字节数、角色和证据引用，不在运行时添加 hash 扫描；
- `formalCandidateEligible` 只有在 channel=candidate、clean checkout 且同时存在 #278/#279 evidence 引用时为 true；
- workflow 只上传候选制品，不执行签名、公证、staple、更新发布或 GitHub Release publish。

## 非目标

- 不在本切片删除 Swift、迁移离线工具或改变产品运行路径；
- 不在本切片申请或使用 Apple Developer 凭据；
- 不宣称 Developer ID、hardened runtime、notarization、Gatekeeper、update feed 或 rollback 已完成；这些属于 #280-E5-03-B；
- `release:publish` 只提供 Forge publisher 配置和显式命令，不由 candidate workflow 自动调用。
